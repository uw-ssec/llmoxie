# Keycloak Sign-in (Stage 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keycloak behind the stage 1 edge, its realm applied from the config
YAML by keycloak-config-cli on every deploy, Keycloak logins (oauth2-proxy) in
front of MLflow and the LiteLLM UI, LiteLLM on the uw-ssec fork with SSO, and
`infra extract` reaching MLflow with a Keycloak token.

**Architecture:** New config (`KeycloakConfig`, `LoginConfig`) and name helpers
in `config/schema.py`; a realm renderer (`resources/keycloak_realm.py`);
Keycloak app, realm job and login apps (`resources/keycloak.py`); new routes in
the edge renderer (`resources/traefik.py`); wiring in `main.py`; a post-`up`
realm-job run in `deployment/deploy.py`; a token for `infra extract` in
`cli.py`. Everything is off unless `keycloak.enabled`, so stage 1 stacks deploy
unchanged.

**Tech Stack:** Python 3.12, Pydantic v2, Pulumi azure-native 3.29 +
pulumi-random, Keycloak 26.x, keycloak-config-cli, oauth2-proxy v7.15.x, Traefik
v3.7, LiteLLM fork v1.108.6, pytest.

**Spec:** `docs/superpowers/specs/2026-11-13-keycloak-azure-design.md`, stage 2
(sections 2.1 to 2.10), Constraints and Anti-goals. It builds on stage 1, which
is on branch `keycloak-service` (PR #242). This branch is `keycloak-sign-in`,
cut from it.

## Global Constraints

- Pixi only: `pixi run -e llmaven pytest ...`, `pixi run -e llmaven verify`.
  Never `pip`, `conda` or `venv`.
- Never run `llmaven infra deploy` (including `--preview`), `destroy`,
  `refresh`, `cancel`, or any `az` command that changes Azure. Deploys are the
  owner's.
- Before the first edit to any file, run
  `pixi run -e llmaven okf search --for-path <file>`. Stop on
  `governance: hold`; keep any `constraint`.
- With `keycloak.enabled: false` (the default), the program produces exactly
  stage 1's resources. Existing tests keep their assertions.
- One Key Vault access policy, one shared identity. Keycloak, the realm job and
  the login apps that read Key Vault use the shared user-assigned identity and
  `depends_on` the shared policy. Never add an `AccessPolicy`
  (`knowledge/bugs/key-vault-access-policy-replace.md`).
- Secrets are generated by Pulumi (`pulumi_random`) into Key Vault through
  `SecretsManager`. No secret value appears in the YAML, in the rendered realm
  document, or in logs.
- Third-party images are pinned by tag and digest: keycloak-config-cli,
  oauth2-proxy, the Keycloak base in its Dockerfile, and the LiteLLM fork
  `ghcr.io/uw-ssec/llmoxie-litellm-fork:v1.108.6@sha256:98070f3fcfb082155d5153bdaddbaa18a1fa05524990e7cb4b8c9fd42e68fbd3`,
  which is amd64 only.
- Azure caps Container App and Container Apps Job names at 32 characters. Names
  come from the helpers in Task 2. Keycloak is `<stack>-keycloak`, the logins
  are `<stack>-ml-auth` and `<stack>-llm-auth`, and the job is
  `<project>-realm-<env>`.
- Realm name defaults to `llmoxie` and is permanent, because it is part of the
  issuer `https://<keycloak.hostname>/realms/<name>`.
- LiteLLM-host behavior (spec 2.6):
  - Public inference and health paths need no login.
  - A browser request with no `Authorization` header needs a Keycloak session
    holding `litellm-admin`.
  - A request with a session cookie passes from any IP once the session checks
    out.
  - A bearer key with no session passes only from `litellm.admin_allowed_ips`.
  - LiteLLM's UI and login paths always need a session, whatever headers come
    with them.
- Commits: conventional (`feat|fix|docs|test(infra|cli|docker|knowledge)`). End
  with `Assisted-by: claude-code:<model id>`; no `Co-Authored-By`, no
  `Signed-off-by`. Stage files by name; never stage `.kube/`, `.impeccable/`,
  `services/`.

## Review Focus

- **A bearer key from a non-allowlisted IP to a LiteLLM management path** gets
  403 and never reaches LiteLLM. Task 7:
  `test_litellm_bearer_key_needs_allowlisted_ip`.
- **LiteLLM's login paths (`/login`, `/v2/login`, `/ui/`, `/sso/`) with a forged
  `Authorization` header from an allowlisted IP** still need a Keycloak session.
  Task 7: `test_litellm_ui_paths_always_need_a_session`.
- **A second realm-job run, with a console-made client present in Keycloak,**
  changes nothing and leaves that client in place. Task 13 checks this against
  real Keycloak and keycloak-config-cli.
- **`keycloak.realm.overrides` that redefines a stack client** (`mlflow-gate`,
  `litellm-gate`, `litellm`, `llmaven-cli`) is a validation error. Task 2:
  `test_overrides_cannot_redefine_stack_clients`.
- **A project name long enough to push a Container App or job name past 32
  characters** is a validation error that names the resource and the limit. Task
  2: `test_long_project_name_is_rejected_per_resource`.
