# Requirements
* [Never drop the llmaven blob container from storage config](keep-llmaven-blob-container.md) - The container looks like a RAG leftover, but removing a container from config deletes its blob data on the next infra deploy; a test pins the list.
* [Stack-managed Foundry accepts traffic only from the Container Apps subnet (implemented, unproven on Azure)](foundry-subnet-only-network-acl.md) - `foundry.enabled` creates default-deny ACLs with one subnet rule; the boundary is the whole environment subnet, not LiteLLM, and no live acceptance has run.
* [Path-level access control uses a Traefik sidecar with an allowlist](traefik-sidecar-allowlist-and-client-ip.md) - Container Apps restricts by IP per app only and front doors can be bypassed through the platform FQDN, so #217 added an optional sidecar; the trusted-peer and forged-header gates are unproven on Azure.
* [Never add a fresh salt key to an existing database, and rotate the master key by migration](litellm-master-and-salt-key.md) - With no LITELLM_SALT_KEY the master key encrypts stored credentials, so replacing it needs a migration, and adding a salt key to existing data breaks decryption.
* [Secret-loading diagnostics stay on pulumi.log](secret-loading-logs-use-pulumi-log.md) - Project owner directive on #134: stdlib logging hides found, loaded and skipped secret names by default, so these messages use pulumi.log and never print values.
* [jsonlines and mlflow are imported by the package but declared only in pixi.toml](pyproject-runtime-deps-gap.md) - The owner ruled that package dependencies go in pyproject.toml so pip users get them; jsonlines and mlflow still violate that, so a pip install lacks them (inferred).
* [Database backups live outside the cluster they protect](backups-outside-the-cluster.md) - Owner directive for the Helm chart in #236: the chart bundles no backup destination and backups never go to the bundled RustFS; the local stack uses a second k3d cluster. Unmerged prototype.
