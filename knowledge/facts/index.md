# Facts
* [Earlier directions that were dropped, and PRs closed with no stated reason](project-history-superseded-directions.md) - Custom proxy, OpenTofu, the Jupyter AI survey and the demo were replaced; #126 and #168 record no rejection reason, so don't read them as design verdicts.
* [Rebrand compatibility plan, and llmaven names that look like deployed state but aren't](rebrand-compat-and-safe-names.md) - The #187 audits recommend one release of overlap for the CLI, env prefix and config filenames, and show several llmaven names are safe to rename.
* [Custom domains are declarative; issuing the certificate stays manual](custom-domains-declarative-certificate-manual.md) - A hostname not in custom_domains is removed by the next deploy, and Pulumi can't issue the managed certificate in one pass because attach, certificate and bind form a cycle.
* [What a fresh stack needs for LiteLLM to start](fresh-stack-startup-requirements.md) - LiteLLM runs migrations at boot and needs a long probe budget, apps must depend on the access policy, and the subnet needs explicit delegation.
* [Managed Redis arrives automatically on the next deploy and is unproven live](managed-redis-rollout-and-limits.md) - max_replicas defaults to 2, so any default stack gains Redis and its cost on the next deploy; cross-replica limit enforcement hasn't been shown on a live stack.
* [Azure E2E through floci-az needs a spike and can't replace a real preview](floci-az-e2e-feasibility.md) - floci-az 0.15.0 documents only Terraform and OpenTofu and has no Container Apps Jobs handler, so #192 starts with a time-boxed spike; a human-approved real preview stays the gate.
* [The LiteLLM image has no pip, wget or curl, and needs mlflow-skinny](litellm-image-install-quirks.md) - Since v1.106.x the image is a uv venv, so the Dockerfile uses ensurepip and re-pins litellm; full mlflow caps cryptography below 47 and reintroduces advisories.
* [Load test fallback detection depends on /model/info, because /v1/messages hides fallbacks](loadtest-fallback-detection.md) - LiteLLM 1.82.3 echoes the alias on /v1/messages and omits the fallback header, so the runner maps x-litellm-model-id; verified locally on 1.82.3 only.
* [ADLS logs, LiteLLM spend logs and MLflow traces are different datasets](request-log-sources-differ.md) - ADLS holds untruncated per-request JSON of successes only, including raw prompts; spend logs may truncate; MLflow traces are a derived view without API keys.
* [Any pyproject.toml edit can stale pixi.lock, and a newer local Pixi hides it](pixi-lock-hash-needs-ci-version.md) - pixi.lock holds a hash for the editable package, so even a description edit fails CI's locked install under 0.63.2 before tests run; a newer Pixi accepted the stale lock on #210.
* [Changing workspace channels re-solves every Pixi environment](pixi-channel-change-resolves-all-envs.md) - Dropping the pytorch channel in #189 made every lock section stale and would have moved Pulumi and azure-native, so infra and backup were restored by hand.
* [Ruff rules are pinned explicitly so hook updates can't widen lint policy](ruff-rules-pinned-explicitly.md) - Ruff 0.16 expanded its defaults, so #210 selects E4, E7, E9 and F; adopting more rules should be its own change.
* [Image builds never run on PRs, and workflow actions are pinned by SHA](image-builds-and-workflow-pinning.md) - build-services.yml runs only after merge, on releases and on dispatch, so PR checks say nothing about images; zizmor requires full-SHA action pins.
* [Docs and comments that disagree with the code at e248584](known-stale-docs.md) - A checked list of stale statements in the rules, workflow docs and deploy code; trust the code, and remove entries as they're fixed.
* [Production-readiness gaps are tracked in #193, and some settings do less than they suggest](production-readiness-gaps.md) - #193 tracks platform gaps; enable_application_insights and daily_data_cap_gb provision nothing, and enable_private_endpoints denies access without creating endpoints.
